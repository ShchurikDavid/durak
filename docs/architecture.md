# Архитектура проекта

Сервер использует CommonJS (`require`), браузер — ES-модули (`import` / `export`).
Сборщика нет. Игровые правила и формат Socket.IO-событий сохранены при рефакторинге.

## Как проходит ход

1. Клиент отправляет `playCard` с индексом карты в последней полученной руке.
2. `socket/handlers.js` проверяет комнату, игрока и состояние партии.
3. `rules.js` проверяет ход. Только сервер меняет игровые карты.
4. Движок перезапускает таймер хода, сервис формирует отдельное состояние для каждого игрока.
5. Клиент получает `updateState`, сохраняет снимок в `session.currentState` и вызывает `render`.
6. Модули интерфейса обновляют карты, плашки, таймеры и результат.

`session.actionPending` блокирует повторную команду до получения состояния.
Отрисовка вызывается явно; второй скрытой подписки на `updateState` нет.

## Границы модулей

- Правила не импортируют Express, Socket.IO или DOM.
- Движок получает `onState`, проверку существования комнаты, таймеры и генератор
  случайных чисел через параметры. В тестах их можно заменить.
- Каждое приложение получает свой `Map` комнат. Импорт `server.js` не запускает порт.
- `createApplication().close()` закрывает соединения и очищает таймеры.
- Клиентские модули используют явные импорты. Общие данные находятся в `core/session.js`.
- `public/js/package.json` задаёт ES-модули для их импорта в Node.js-тестах.
- CSS не создаётся строками в JavaScript. Порядок стилей: `base.css`, `table.css`,
  `icons.css`, `stability.css`, `create-room.css`; последние файлы уточняют оформление.
- При изменении правил добавляйте тест и проверяйте соответствующую подсветку в `ui/highlights.js`.

## Сетевой контракт

Клиент → сервер: `getRooms`, `createRoom`, `joinRoom`, `leaveRoom`, `playCard`, `transferCard`, `bito`,
`take`, `restartGame`.

Сервер → клиент: `roomLobby`, `roomList`, `roomCreated`, `joinedRoom`, `roomError`,
`roomClosed`, `updateState`. Поля снимка состояния определены в `publicStateFor`.

`createRoom` принимает `mode` (24/36/52/54), `maxPlayers` (2–4) и
`gameType` (`throwIn` или `transfer`). Неизвестный тип заменяется на `throwIn`.
`transferCard` принимает индекс карты в руке. Правило `canTransfer` проверяет
достоинство, отсутствие защиты, лимит захода и размер руки следующего игрока.
Снимок содержит `canTransfer` и `transferCardIndexes` для подсветки. Выбор действия
хранится в `session.transferMode` и сбрасывается при новом состоянии сервера.
`roundAttackerIndex` сохраняет начавшего заход для порядка добора после переводов.

## Существующие ограничения

- Комнаты хранятся в памяти; перезапуск сервера завершает их.
- `src/auth.js` хранит аккаунты и сессии в SQLite. `public/js/auth.js` управляет
  формами аккаунта и сменой ника в настройках. HTTP API: `GET /api/auth/me`,
  `POST /api/auth/register`, `/api/auth/login`, `/api/auth/logout`, `/api/auth/name`.
  Смена ника обновляет текущие комнаты и отправляет `profileUpdated` сессиям игрока.
  Схема SQLite версии 2 добавляет `sessions.guest_name` с сохранением существующих данных.
- Socket.IO определяет игрока по HttpOnly-cookie; присланный клиентом `userId`
  игнорируется. Ник аккаунта берётся из базы, ник гостя проверяется на сервере.
  Истёкшая или отозванная сессия вызывает `authExpired` и отключение соединения.
- Первое успешное «Бито» увеличивает лимит атак с 5 до 6; взятие до первого отбоя — нет.
- Джокеры разрешены только для защиты своего цвета. Если колода и стол пусты,
  а у оставшихся игроков только джокеры, объявляется ничья.

## Android / React Native

`mobile/App.tsx` и `mobile/styles.ts` — самостоятельные нативные экраны. В APK
включается Hermes-бандл: WebView, сайт и Metro для запуска не нужны.
`mobile/local-game.js` запускает общие правила, движок и обработчики команд
в памяти телефона; транспорт заменён локальными обработчиками, соперники — боты.
`mobile/network.ts` подключает те же экраны к HTTP API аккаунтов и Socket.IO.
Настройки ника, сервера и вибрации сохраняются через AsyncStorage. Пароль не сохраняется.
Bluetooth и сервер на телефоне не реализованы. Сетевая игра использует Node-сервер.

## Проверки

Node.js 24 или новее. После `npm ci` запустите `npm run check`: ESLint, Prettier, TypeScript и тесты.
`npm run format` форматирует исходники. Интерфейс дополнительно проверяйте в браузере:
на телефоне, при смене звука, выборе колоды и переподключении.
